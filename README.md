# 물류비 인사이트

라벨관리시스템과 분리된 물류비 관리 웹 애플리케이션입니다. 운영 서비스와 외부 AI에는 연결하지 않습니다. 화면 디자인보다 입력·집계·검증 흐름을 우선 구현했습니다.

## 실제 앱과 검토본의 구분

실제 개발·검증의 기준은 `npm start`로 실행하는 로그인·SQLite 기반 앱입니다. `npm run test:app`은 임시 DB와 임의 생성 테스트 비밀번호를 사용하여 실제 브라우저의 초기 관리자 등록·빈 자료 시작·센터/매장 등록·비용/건수 입력·XLSX 업로드·DB 재조회·서버 재시작·3개 계정·조회 권한·백업을 검증합니다. 기존 `data/`의 DB와 계정은 변경하지 않습니다. 검토 HTML은 별도의 예시 화면이며 실제 앱 로그인·DB 저장의 증거로 사용하지 않습니다.

업무용 신규 시작은 ‘빈 자료로 시작’을 선택하세요. 예시 매장·센터·관리그룹은 등록되지 않으며 국가 KR과 기본 비용 항목만 준비됩니다. 대시보드의 ‘업무 시작 설정’에서 국가/센터 → 관리그룹/매장 → 비용/건수 순서로 등록합니다. 검토본의 예시 자료는 실제 DB로 자동 전송하지 않습니다.

독립 Lightsail 서버에서 앱을 실행 중입니다. 이 개발 환경에서는 임시 DB로 검증하고, 서버 적용은 배포 브랜치 업데이트와 scm-logistics 서비스 재시작으로 진행합니다. 기존 업무 DB를 초기화하거나 예시 데이터를 자동 업로드하지 않습니다.

## 화면을 보면서 수정하기

예시 화면을 바로 검토하는 방법은 [REVIEW.md](REVIEW.md)를 참고하세요. `npm run review:build`로 서버·로그인 없이 사용할 수 있는 단일 HTML 검토본을 만들고, `npm run review`로 로컬 검토 서버를 시작합니다. 실제 업무 DB와 분리되어 있습니다. 변경 요청을 받으면 같은 화면 코드를 수정하고 새 검토본을 제공할 수 있습니다.

## 개발 환경

Node.js 24 이상이 필요합니다(검증 환경 24.19). 서버는 Node 내장 SQLite를 사용합니다. 엑셀용 ExcelJS는 lockfile로 고정합니다.

```sh
cd /workspace/Logistics_Cost_management
npm ci
npm test
npm start
```

Node 서버가 기본적으로 127.0.0.1의 3000번 포트에서 실행됩니다. 최초 실행은 로그인 화면에서 관리자 등록(서버 로컬 접속) 또는 `npm run admin:init`을 진행하세요. 관리자 비밀번호는 직접 정하며 기본 계정은 없습니다. 로그인 후 예시 데이터 또는 빈 자료를 선택합니다. 종료는 Ctrl+C입니다. 이 작업의 개발 서버만 종료하세요.

## 기준정보를 먼저 등록하세요

- 국가 · 물류센터: 국가코드/국가명과 센터를 연결합니다. 국가코드는 영문 2자리 형식과 중복을 검증합니다. 공식 코드 사전 대조는 하지 않습니다.
- 매장 마스터: 관리그룹 → 매장코드·매장명·소속 그룹 순서로 등록합니다. 코드는 영문/숫자/하이픈/밑줄 1~20자이며 대문자로 저장합니다. 내부 ID는 표시 코드·이름과 별도로 보존합니다.
- 비용 항목: 추가·기본 단위 변경·사용 제외·재사용을 지원합니다. 지급임차료, B2C 출고비, B2B 출고비, 특송비, 용차임, 기타 물류비, 입고비, 임가공비(세트포장 등), 임가공비(라벨링)을 기본 제공하며 포워딩·관세 등 기존 항목도 유지합니다.
- 사용 제외는 신규 입력·업로드를 제한하며 기존 내역은 보존합니다. 국가·관리그룹은 등록 당시 소속을 저장합니다.

## 세 종류의 입력, 하나의 집계

1. 물류센터 비용 · 건수: 월·센터를 선택하고 행별로 비용/건수, B2C/B2B/공통, 매장을 지정합니다.
2. 수출입 비용: 센터 없이 수출입관리번호·수출/수입·선적 국가·출발국·도착국을 입력합니다. 포워딩·관세 등 비용을 여러 행으로 기록합니다.
3. 공통 비용: 센터나 수출입 건 없이 국가·관리그룹/매장에 귀속합니다.

비용은 수량×단가 또는 금액 직접 입력을 지원합니다. 수량·단가는 소수 셋째 자리까지 허용하며 공급가액을 원 단위 반올림합니다. 금액 상한은 행당 1조 원입니다. 건수는 물류센터의 B2C/B2B 정수 지표로 저장하고 비용 합계에 절대 포함하지 않습니다. 청구 단위 ‘건’으로 입력한 비용도 데이터유형이 비용이면 금액에 포함됩니다.

매장 미지정은 센터 공통/미배분으로 관리하며 임의로 매장에 배분하지 않습니다. 원 청구 총액 자동 안분·대사는 아직 없습니다. 동일 실제 비용을 센터/수출입 양쪽에 중복 입력하지 마세요.

## 계산 기준

- 총비용 = 필터에 맞는 비용 레코드의 공급가액 합계. 건수는 제외합니다. 금액 단위는 모두 KRW입니다.
- 센터 출고 건당 비용 = 센터 비용 ÷ 센터 출고량. 수출입·공통비를 센터 건당 비용에 섞지 않습니다.
- 전체 매출 대비 비용률 = 선택한 전체 비용 ÷ 입력한 동일 범위 매출 × 100. B2C/B2B별 매출은 아직 분리 등록하지 않으므로 업무 필터 사용 시 매출 비율은 미계산입니다.
- 건수 레코드가 있으면 이를 출고량에 사용합니다. 월·센터·업무별 센터 공통 건수가 있으면 매장별 건수와 중복 합산하지 않습니다. 해당 범위에 건수 레코드가 없으면 출고량을 확인할 수 없으며 기존 별도 물동량 지표로 대체하지 않습니다. 일부 매장의 건수만 입력하면 그 등록 범위의 합계이므로 전체 입력 여부를 확인하세요.
- B2C/B2B 비용 증감 분석은 같은 범위의 해당 출고비 항목과 건수를 연결합니다. 전월 평균 건당 비용을 기준으로 `건수 변화 효과=(당월건수-전월건수)×전월건당비용`, `건당비용 변화 효과=당월건수×(당월건당비용-전월건당비용)`을 계산합니다. 두 효과의 합은 비용 증감과 일치합니다. 실제 계약 단가나 인과관계를 단정하지 않습니다.
- 전월 또는 분모가 없으면 미계산으로 표시합니다. 데이터 유형 ‘건수만’을 선택하면 금액 합계는 0입니다. 비용항목 필터와 독립적으로 업무별 출고비/건수를 짝지어 증감 근거를 표시합니다.
- 센터 선택 시 그 센터 내역만 포함하므로 전체 수출입·공통비를 보려면 전체 센터/전체 유형으로 조회하세요.
- 부가세는 신규 입력·양식·보고서·화면 합계에서 제외했습니다. 기존 기록의 부가세 속성은 보존하지만 사용하지 않습니다.

## 엑셀과 기존 관리표 업로드

비용 내역 · 업로드에서 최신 .xlsx 양식 또는 CSV를 다운로드합니다. 엑셀은 작성 안내/통합 입력/기준정보/작성 예시 시트를 포함합니다. 통합 입력 시트에 최대 2,000건·5MB를 입력하세요. 미리 구성된 드롭다운은 500개 입력행에 적용됩니다. 입력 열에는 수식 대신 값을 사용합니다. 구형 .xls는 .xlsx로 저장하세요.

통합 열: 월,비용유형,데이터유형,국가코드,센터,수출입관리번호,수출입구분,출발국,도착국,업무구분,매장코드,매장명,관리그룹,비용항목,청구단위,수량,단가,값,메모.

- 비용유형: 물류센터/수출입/공통. 데이터유형: 비용/건수.
- 비용의 ‘값’에 금액을 직접 입력하거나 비워 두고 수량·단가로 계산합니다. 건수는 값 또는 수량에 입력합니다.
- 매장명은 참고용이며 코드로 식별합니다. 매장을 지정하면 현재 마스터에서 소속 그룹을 결정합니다. 센터 공통은 ‘센터 공통’으로 입력합니다.
- 화면으로 제공된 기존 관리표의 `년/월,물류센터,계정,매장코드,매장명,구분,구분2,값` 구조도 지원합니다. 구분/구분2의 건수·건/수는 지표, 나머지는 구분2의 비용 항목으로 가져옵니다. 년·분기 등 부가 열은 무시합니다. 물류센터명·매장코드·비용항목을 마스터에 먼저 등록하세요. 건수 행의 계정은 B2C/B2B가 필요합니다.
- 실제 파일의 이름이나 열이 다르면 조정이 필요합니다. `-`는 0인지 누락인지 확인하기 전 자동 변환하지 않고 오류로 표시합니다. 공백 행은 건너뛰며 숫자 0은 보존합니다.
- 기존 6/8/9열 센터 비용 양식도 지원합니다. 과거 매장명 헤더는 이름으로 매칭합니다.
- 업로드는 검토만 수행합니다. 오류 행·비용과 건수 합계·첫 20건 미리보기를 확인하고 일괄 저장을 눌러야 반영됩니다. 오류가 하나라도 있으면 전체 차단합니다.
- 동일 레코드의 재업로드와 파일 내부 중복을 차단합니다(월·유형·업무·귀속·항목·수량·단가·금액·메모 등 일치 기준). 실제 별도 청구가 동일하면 메모로 구분하세요. 저장 시 마스터와 중복을 재검증합니다.

## 서버 저장 · 사용자 · 변경 이력

자료는 서버 SQLite DB(`data/logistics.sqlite`)에 저장하며 같은 서버를 사용하는 계정끼리 공유됩니다. 기존 브라우저 localStorage는 삭제하지 않지만 자동으로 서버에 가져오지 않습니다. 실제 자료 업로드는 사이트 검증 후 진행합니다. 화면 이동 시 입력 초안은 유지되지만 저장 전 새로고침하면 사라집니다.

- 관리자: 모든 자료와 기준정보, 계정·권한, 백업·복원·변경 이력 관리.
- 입력 담당: 비용·건수 입력/수정/삭제와 ERP 매출 업로드. 기준정보·사용자·백업 권한은 없습니다.
- 조회 전용: 대시보드·내역 조회와 엑셀 양식/보고서 다운로드. API도 저장을 차단합니다.
- 최초 관리자는 화면(서버 로컬 연결만 허용) 또는 `npm run admin:init`으로 등록합니다. CLI는 비밀번호를 화면에 표시하지 않습니다.
- 비밀번호는 scrypt 해시로 저장합니다. 세션은 HttpOnly/SameSite 쿠키로 관리하며 8시간 뒤 만료됩니다. 로그아웃·권한 변경·사용 중지·비밀번호 변경은 관련 세션을 해제합니다. API는 Origin과 CSRF 토큰도 검사합니다.
- 저장 시 서버가 금액·건수·귀속값을 재검증합니다. 자료 버전이 달라졌으면 409 충돌로 차단하여 다른 사용자의 변경을 덮어쓰지 않습니다. 입력을 보관하고 새로고침 후 최신 자료를 확인하세요.
- 비용 내역의 수정 버튼으로 편집할 수 있으며 등록·수정·삭제 전후 값은 서버 변경 이력에 남습니다. 관리자는 최근 200개 작업을 조회할 수 있습니다.

## 백업 · 복원

계정 · 백업 · 이력 화면에서 전체 업무 자료 JSON을 다운로드할 수 있습니다. 이 파일은 기준정보·비용·건수·물동량·매출·사유를 포함하며 계정·비밀번호·세션·이력은 포함하지 않습니다. 파일 복원 또는 서버의 최근 20개 자동 보관 시점 복원에는 관리자 비밀번호를 다시 입력해야 합니다. 복원 전의 상태도 자동 보관하고, 검증 실패 시 전체 복원을 취소합니다. 복원은 현재 업무 자료 전체를 교체합니다.

계정·변경 이력까지 포함한 DB 재해복구 백업은 `npm run db:backup -- /원하는/새파일.sqlite`로 만듭니다. SQLite 온라인 백업 API를 사용하므로 WAL 파일을 임의로 복사하지 않습니다. 이미 존재하는 파일은 덮어쓰지 않습니다. 결과에는 비밀번호 해시와 세션도 포함하므로 접근을 제한하고 서버 외부에 별도로 보관하세요. 데이터 폴더·백업은 Git과 Docker 빌드에 포함되지 않습니다. 자동 스냅샷은 같은 DB 안에 저장되므로 서버 장애 대비 외부 백업을 대체하지 않습니다. 일일 로컬 백업 작업·한국시간 02:30 타이머·30일 보관 파일은 deploy/backup에 준비했습니다. 실제 예약 실행과 외부 백업은 서버 선정 후 활성화합니다.

## 배포 · 검증 상태

`DEPLOYMENT.md`, `Dockerfile`, `compose.yaml`을 준비했습니다. 외부 서버는 아직 정하지 않았으므로 외부 사이트 배포는 하지 않았습니다. 운영 라벨관리시스템은 변경하지 않습니다. Docker 이미지 빌드와 임시 Compose 서버의 재시작·검증 백업·복원도 확인했습니다. 실제 호스팅·HTTPS·백업 예약 활성화는 아직 하지 않았습니다.

`npm test`는 기존 계산/엑셀/유형별 집계와 인증·권한·서버 검증·동시 수정·이력·백업/복원·서버 재시작·DB 파일 백업을 검사합니다. 실제 브라우저에서도 최초 계정 설정·비용 수정·새로고침 유지·다른 브라우저 조회·자료 복원 등을 검증했습니다. 사용자 실제 파일과의 합계 대사는 업로드를 시작할 때 수행해야 합니다.

현재는 단일 서버 개발용 버전입니다. 사업장별 자료 격리, 2단계 인증·비밀번호 분실 재설정, 대용량 분할 저장, 실시간 환율 조회·환차손익·세금 신고·실제 운송서류 연결은 후속 범위입니다. 외부 공개 전 도메인·HTTPS·저장 볼륨·외부 백업을 구성해야 합니다.

## 수출입 추가 정보

수출입 입력·수정 화면에서 인코텀즈(EXW/FCA/CPT/CIP/DAP/DPU/DDP/FAS/FOB/CFR/CIF)와 화물 타입(LCL/FCL/AIR)을 선택합니다. 미지정도 허용하며 기존 자료를 임의로 채우지 않습니다. 내역·업로드 미리보기·보고서에 함께 표시하고 저장합니다. 이 선택은 비용을 자동 변경하거나 운송·통관 책임을 판정하지 않습니다.

최신 통합 엑셀/CSV의 마지막에 ‘인코텀즈’, ‘화물타입’ 열을 추가했습니다. 엑셀 입력 시트에 드롭다운이 있고 수출입 작성 예시에도 값이 포함됩니다. 이전 19열 통합 양식도 그대로 지원하며 해당 필드는 미지정으로 가져옵니다. 중복 검사는 인코텀즈와 화물 타입도 구분합니다.

수출입 문서 식별용으로 `CIPL NO.`와 `내부 관리번호`를 별도 입력·수정·조회할 수 있습니다. 기존 수출입관리번호는 유지합니다. 두 필드는 선택 사항이며 문자 형식으로 각 100자까지 저장해 앞자리 0을 보존합니다. 최신 통합 엑셀/CSV의 마지막에 두 열을 추가했고, 작성 예시·보고서·업로드 미리보기·중복 검사에도 반영했습니다. 이전 19열/21열 통합 양식은 해당 필드를 빈 값으로 읽습니다.

## 인코텀즈별 유동 입력

수출입 화면의 입력 도우미는 E/F/C/D 그룹과 수출자·수입자 관점에 따라 권장 비용 그룹을 강조합니다. 화물 타입은 국제운송료의 해상/항공 안내에 반영하며, 해상 전용 FAS/FOB/CFR/CIF에 AIR를 지정하면 검토 안내를 표시합니다. 조건을 바꿔도 입력한 행·금액은 삭제하거나 자동 조정하지 않습니다.

권장 버튼으로 포워딩 아래 국제운송료/출발지 비용/도착지 비용/적하보험료/기타·일괄 청구 행을 추가하고 합계 금액을 직접 입력할 수 있습니다. 추천 밖의 비용도 등록 가능합니다. CIF/CIP는 수출자의 보험 부보 의무를 안내하지만 일괄 청구에 포함되었을 수 있어 누락 여부를 자동 단정하지 않습니다. DAP/DPU/DDP의 수입통관·관세·하역 차이도 안내합니다.

지정 장소·항구를 선택 사항으로 저장하고 실제 계약의 별도 약정을 확인하도록 안내합니다. 안내는 기본 규칙이며 운송 계약이나 책임을 확정하는 기능은 아닙니다. 일괄 청구와 그 상세를 중복 입력하지 마세요. 최신 통합 엑셀의 마지막 두 열은 비용그룹·지정장소이며 이전 19/21/23열 양식도 지원합니다.

## 수출입 외화 · 적용 환율

비용 행의 입력 방식을 ‘외화금액 × 환율’로 선택하면 통화, 외화 금액, 적용 환율, 외화 기준단위(1/100/1000), 환율 기준일을 입력할 수 있습니다. 수출·수입 모두 지원합니다. 예: USD 100 × 1,350원 ÷ 1 = 135,000원, JPY 10,000 × 950원 ÷ 100 = 95,000원. 외화와 기존 원화 행을 한 수출입 건에 함께 입력할 수 있습니다.

원화 환산액은 반올림한 정수이며 총비용은 이 원화 금액만 합산합니다. 외화 금액 자체를 원화와 더하지 않습니다. 외화 금액은 소수 4자리, 환율은 소수 6자리까지 허용하며 환율은 양수입니다. 서버에서도 환산을 다시 계산해 원화 금액이 일치하지 않으면 저장을 차단합니다. 외화 금액·입력 환율·적용단위·선택 기준일은 수정/내역/보고서/백업에도 보관합니다. 기준일이 있어도 실시간 환율을 자동 조회하거나 국가에서 환율을 추정하지 않습니다.

최신 통합 엑셀의 마지막 다섯 열은 통화·외화금액·적용환율·환율적용단위·환율기준일입니다. 외화 통화를 지정하면 외화금액과 적용환율로 계산하며, 값 열에도 원화 금액을 넣었다면 환산액과 일치하는지 검증합니다. 통화 공란 또는 KRW는 기존 원화 입력으로 처리하고, 외화 금액·환율만 입력한 혼합 자료는 오류로 표시합니다. 이전 19/21/23/25열 통합 양식은 원화 자료로 지원합니다.

### 권장 비용 행 자동 생성

수출입 화면에서 인코텀즈 또는 수출/수입 관점을 변경하면 권장 비용 그룹을 아래 표에 자동 생성합니다. 예를 들어 수출 CIF는 국제운송료·출발지 비용·적하보험료를 포워딩 항목의 금액 직접 입력 행으로 준비합니다. 기존에 같은 그룹 행이 있으면 중복 생성하지 않습니다. 화물 타입 변경이나 화면 이동만으로 행을 추가하지 않습니다.

권장 그룹 버튼은 기존 행으로 이동하고, 아직 없는 추가 그룹만 새로 만듭니다. 조건 변경 시 더 이상 권장되지 않는 미입력 자동 행만 정리하며 금액(0 포함)·외화 근거·메모를 입력했거나 직접 수정한 행은 보존합니다. 입력하지 않은 자동 행은 저장에서 제외합니다. 자동 생성 여부는 초안 전용 표시로, 금액이나 비용 확정 상태를 의미하지 않습니다.

## 수출입 건별 조회

‘수출입 건별 조회’에서 수출입관리번호·CIPL NO.·내부 관리번호를 검색하고 인코텀즈·화물 타입으로 좁힐 수 있습니다. 상단 선택 월 또는 전체 월을 조회하며 국가·매장·비용항목 등 기존 필터도 함께 적용됩니다. 항목을 제한하면 해당 항목의 부분합입니다.

월·수출입관리번호·수출/수입·선적 국가·출발국·도착국이 같은 비용을 한 건으로 묶습니다. 건수 지표와 센터비·공통비는 이 화면의 집계에서 제외합니다. 서로 다른 청구 통화를 더하지 않고 개별 원화 환산액만 합산합니다. 같은 건에 여러 인코텀즈나 문서번호가 있으면 값들을 함께 표시해 한 값으로 단정하지 않습니다.

상세를 펼치면 비용 그룹별 원화 합계와 각 매장의 항목·외화 환산 근거를 확인할 수 있습니다. 이 화면의 보고서 다운로드는 현재 조회 조건의 건별 합계 CSV이며 비용 내역 화면의 행별 보고서와 구분됩니다.

## 비용 내역 검색 · 선택정보 확인

비용 내역 화면에서 문서번호·매장코드/매장명·비용항목·메모 등을 검색할 수 있습니다. 상단 월·국가·센터·매장 필터와 함께 적용됩니다. 현재 보이는 내역 수와 원화 비용 합계를 표시하며, 이 화면의 보고서 다운로드도 검색·선택정보 필터 결과만 내보냅니다.

수출입 자료의 문서번호 미입력, 인코텀즈·화물 미지정, 비용 그룹 미분류, 외화 비용의 환율 기준일 미지정을 따로 조회할 수 있습니다. 이는 선택정보 확인용이며 저장 오류나 필수 입력으로 바꾸지 않습니다. 보험료 행의 부재를 누락으로 추정하지 않습니다. 해당 내역을 수정하면 현재 검색 조건에 맞춰 결과와 합계를 다시 계산합니다.

## 컨테이너 타입 · 지정 장소 선택정보

FCL 화물은 일반(DRY), 하이큐빅(HC), 냉장·냉동(REEFER), 오픈톱(OT), 플랫랙(FR), 탱크(TANK), 기타(OTHER)를 선택할 수 있습니다. 미지정도 허용합니다. LCL/AIR에서는 이 필드를 숨기며, 해당 타입으로 변경해 저장하면 적용되지 않는 컨테이너 값은 비웁니다. 다른 비용·금액·문서번호는 그대로 유지됩니다.

지정 장소·항구는 필수가 아니며 ‘지정 장소·항구 (선택)’을 펼쳐 입력합니다. 기존 값이 있으면 펼쳐 표시합니다. C/D 조건에서 운송비 부담 범위를 확인하는 참고 정보이며, 비워 두어도 저장 가능합니다. 내역·건별 조회·보고서에 컨테이너 타입을 반영하며 최신 엑셀의 마지막에 ‘컨테이너타입’ 열을 추가했습니다. 이전 30열 외화 양식도 계속 지원합니다.

수출입 입력·수정·건별 조회의 월과 국가는 ‘선적 월’, ‘선적 국가’로 표기합니다. 센터·공통 비용은 ‘비용 월/국가’, 지표·사유 입력은 ‘기준 월’로 표시합니다. 표기만 변경하며 기존 저장 필드·값과 엑셀의 월/국가코드 열은 유지합니다.

### 대시보드 기간 비교 및 복수 필터

조회 월·국가·센터·업무·비용 유형·비용 항목·관리그룹·매장은 체크박스로 복수 선택합니다. 데이터 유형 필터는 제공하지 않으며 비용과 건수를 자동으로 구분해 비용 합계에는 비용만, 출고량 KPI에는 건수를 사용합니다. 같은 필터 안의 선택은 OR, 서로 다른 필터는 AND로 결합합니다. ‘전체’를 누르거나 마지막 항목을 해제하면 해당 필터 조건을 해제합니다. 관리그룹과 매장은 하나의 계층형 필터입니다. 그룹을 펼쳐 매장을 선택하거나 그룹 전체를 선택할 수 있습니다. 서로 다른 그룹의 매장도 함께 선택하며, 그룹 전체 선택에는 해당 그룹의 센터 공통 자료도 포함됩니다. 과거 자료는 입력 당시 관리그룹 기준으로 표시하고 사용 제외된 매장도 과거 조회에 남깁니다. 그룹 공통 출고량·매출과 상세 매장이 같이 선택되면 같은 그룹의 공통 지표를 우선하여 중복 합산을 방지합니다. 건수는 비용 합계에 포함되지 않습니다.

MoM은 전월, YoY는 전년 동월, YTD는 1월~조회 월 누계, YTD 전년 대비는 전년 같은 누계, QoQ는 해당 분기 전체와 직전 분기 전체를 비교합니다. 모든 비교 기간에 동일한 복수 필터를 적용합니다. 그래프는 기간별 월별 비용과 비교 비용, 조회 출고량을 보여주고 자료 없는 월은 —로 표시합니다. 누계 KPI는 비용·출고량·매출을 각각 합산한 뒤 나누어 계산합니다. 월별 목표 관리와 목표 대비 UI는 제공하지 않습니다. 이전 목표 데이터가 있는 백업은 호환을 위해 보존합니다.

### 비용 대분류·중분류

비용 항목은 하나의 계층형 드롭다운입니다. 대분류를 펼치면 중분류 체크박스가 나오며, 서로 다른 대분류의 중분류를 함께 선택할 수 있습니다. 대분류의 ‘전체 선택’은 하위 중분류를 모두 선택/해제하며 일부만 선택되면 부분 선택으로 표시합니다. 최상단 ‘전체 비용 항목’은 필터 조건을 해제합니다. 선택이 하나도 남지 않아도 전체 조회로 돌아갑니다. KPI·그래프·비교 기간·내역·CSV 보고서에 동일하게 적용하며, 분류를 펼치거나 접는 것만으로 집계 범위는 바뀌지 않습니다.

‘비용 항목 기준정보’에서 대분류 이름과 중분류 항목을 추가하고, 기존 항목의 대분류를 변경할 수 있습니다. 기존 항목은 보관·임차비/입출고비/운송·배송비/임가공비/포워딩/관세/기타 비용으로 기본 표시되며 직접 수정할 수 있습니다. 건수는 별도 ‘물동량 · 건수’ 분류입니다. 입력 화면의 항목 드롭다운도 대분류별로 묶어 보여줍니다.

중분류는 기존 비용항목 이름을 그대로 사용하므로 기존 자료와 엑셀 양식을 변경할 필요가 없습니다. 엑셀에는 기존 ‘비용항목’ 열에 중분류를 입력하면 마스터의 대분류에 연결됩니다. 중분류 이름은 전체 마스터에서 고유해야 합니다. 분류를 바꾸면 과거 자료도 현재 마스터 분류로 조회되며 원래 비용 금액은 바뀌지 않습니다. 대분류 필드는 선택적 메타데이터로 저장하므로 과거 백업도 호환됩니다.

대시보드의 ‘비용 항목별 금액 비교’는 가로 막대그래프로 비용을 비교합니다. 대분류별/중분류별로 전환하며 조회·비교 기간의 금액을 나란히 표시합니다. 현재 복수 필터와 MoM·YoY·YTD·YTD 전년 대비·QoQ 기간을 동일하게 적용합니다. 건수는 제외하며 자료 없는 항목은 —로 표시합니다. 항목별 조회·비교 월 자료가 모두 있을 때만 증감률을 계산합니다. 항목이 많으면 그래프 안에서 스크롤할 수 있습니다.

조회 월은 비연속 월과 여러 연도를 함께 선택할 수 있습니다. MoM은 각 선택 월의 전월, YoY는 전년 동월을 연결해 비교합니다. YTD는 선택한 연도별 마지막 선택 월까지의 누계, QoQ는 선택 월이 속한 분기 전체를 합산합니다. 누계와 분기가 겹쳐도 같은 월은 한 번만 포함합니다. 조회·비교 월 목록을 화면에서 확인할 수 있으며 일부 월의 자료가 없으면 증감률을 표시하지 않습니다. 조회·비교 양쪽에 같은 월이 포함될 수 있습니다. 비용 내역·매출·보고서에도 선택한 월들을 적용합니다. 입력 화면과 엑셀 예시 월은 선택 월 중 마지막 월을 기본값으로 사용하고 직접 변경할 수 있습니다. 월이 많으면 그래프를 가로 스크롤합니다.

‘비용 항목별 금액 비교’ 옆의 ‘매장별 비용 비교’는 동일한 월·센터·항목·관리그룹/매장 조건으로 매장별 조회·비교 금액을 표시합니다. 매장코드와 입력 당시 관리그룹 조합별로 집계하며, 같은 매장이 다른 관리그룹으로 기록된 경우 그룹별로 구분합니다. 비용만 합산하고 건수는 제외합니다. 매장 미지정 비용은 그룹별 공통 비용으로 별도 표시하며 매장에 임의 배분하지 않습니다. 금액이 큰 순으로 정렬하고 자료 없는 기간은 —로 표시합니다. 데스크톱은 두 그래프를 좌우에, 좁은 화면은 위아래로 배치합니다.

### 비용 증감과 운영 효율 그래프

대시보드에 ‘출고량 · 건당 비용 추이’와 ‘비용 증감 요인 워터폴’을 제공합니다. 현재의 복수 필터와 조회·비교 기간을 사용합니다. 운영 효율 그래프는 양 기간에 포함된 월을 중복 없이 날짜순으로 표시합니다. 출고량은 왼쪽 축의 막대, 센터 비용÷출고량은 오른쪽 축의 선이며 단위가 달라 높이를 직접 비교하지 않습니다. 수출입·공통 비용은 건당 비용 분자에서 제외합니다. 월별 비용이나 출고량이 없거나 출고량이 0이면 건당 비용 점과 그 점으로 이어지는 선을 표시하지 않습니다.

워터폴은 비교 기간 합계에서 시작하여 중분류 항목별 증감을 누적한 뒤 조회 기간 합계에 도달합니다. 증가와 감소를 색으로 구분하고 변화의 절댓값이 큰 순서로 표시합니다. 건수는 제외하며 점검되는 합계는 ‘비교 비용 + 증감 합계 = 조회 비용’입니다. YTD는 비교 없는 누계이므로 워터폴 대신 비교 기준 안내를 표시합니다. 어느 한 기간의 월별 비용 자료가 부족하면 누락 월을 0으로 간주하지 않고 그래프를 계산하지 않습니다. 실제 증가 원인은 그래프만으로 단정하지 않습니다.

## 독립 실행 패키지

`npm run release:build`는 기존 DB·계정·자격증명·node_modules를 제외한 소스 실행 ZIP과 SHA-256을 `artifacts/`에 만듭니다. 실행 안내는 [START-HERE.md](START-HERE.md)를 참고하세요. 사용자는 독립 AWS 서버를 선택했고, 실시간 요금 확인과 생성 승인은 아직 남아 있습니다. 비용 검토안은 [deploy/aws/PLAN.md](deploy/aws/PLAN.md)에 있습니다.

### 매장 마스터 일괄 등록

매장 마스터 화면의 전용 엑셀 양식은 `매장코드`·`매장명`·`관리그룹`(필수), `사용상태`(선택) 네 열입니다. 사용상태는 사용/사용 제외이며 빈 칸은 신규 매장 사용, 기존 매장 상태 유지입니다. 코드는 텍스트 형식으로 앞자리 0을 보존하고 영문은 대문자로 저장합니다. 기존 코드는 ID를 유지해 수정하고 새 코드는 추가합니다. 파일에 없는 매장은 삭제하지 않으며 과거 비용의 매장 ID·관리그룹을 변경하지 않습니다.

전용 입력 시트와 별도의 작성 예시·관리그룹 참고 시트를 제공합니다. 최대 2,000행, 파일 10MB 이하이며 XLSX·UTF-8 CSV를 지원합니다. 오류가 하나라도 있으면 전체 저장을 막고 미리보기에 표시합니다. 파일 내 코드 중복·최종 매장명 중복·잘못된 상태·누락 필수값·수식·숫자형 매장코드를 검사합니다. 미등록 그룹은 기본 차단하며 ‘미등록 관리그룹도 함께 생성’을 선택하면 새 그룹 목록을 검토한 뒤 매장과 함께 저장합니다. 검토 중 기준정보가 바뀌면 재업로드해야 합니다. 이 기능은 관리자만 사용할 수 있습니다.

## 매출 관리와 물동량 입력 제거

‘물동량 · 매출’ 화면을 ‘매출 관리’로 전환했습니다. 별도 물동량 입력 창과 ‘증감 사유·조치 계획’ 메뉴/화면은 제거했습니다. 과거 `activity`의 물동량·매출 및 `notes` 기록은 DB와 백업에 그대로 남기며 삭제하지 않습니다. 출고량과 건당 비용의 분모는 `costs`의 건수 레코드만 사용합니다. ERP 판매수량을 출고 건수로 사용하지 않습니다.

ERP XLSX/UTF-8 CSV 원장의 매출일자·매장코드·상품매출을 읽습니다. 매장코드로 연결하며 매장명은 참고값입니다. 이름이 달라도 업로드를 허용하고 경고를 표시하며 매장 마스터 이름을 변경하지 않습니다. 금액 기준은 상품매출(기본)/순매출/총매출 중 명시적으로 선택하며 세금·환율을 자동 추정하지 않습니다. 원장 첫 20행에서 헤더를 찾아 최대 50,000행·파일 10MB까지 처리합니다. 월·매장별 합계는 음수 반품을 포함하며 소수 6자리까지 합산 후 원 단위 반올림합니다. 미등록 매장코드·잘못된 날짜·수식·숫자형 매장코드가 있으면 저장을 막습니다.

업로드는 미리보기 후 ‘해당 월·매장 전체 원장’ 확인을 거쳐 저장합니다. 이미 등록된 월·매장은 기존 ID와 관리그룹을 유지해 교체하고 파일에 없는 자료는 보존합니다. 같은 파일 재업로드는 금액/기준/원장 행 수가 같으면 변경 없음이며 추가 합산하지 않습니다. 원장 내부의 동일 금액 행은 정상 거래와 구분할 전표번호가 없으므로 자동 제거하지 않습니다. ERP에서 중복 없는 원장을 준비하세요. 월·매장의 일부 거래만 추가 업로드하면 그 합계로 교체되므로 전체 원장이 필요합니다.

새 ERP 자료는 선택적 `sales` 배열에 저장합니다. 과거 백업에 이 배열이 없어도 열 수 있습니다. ERP 자료가 등록된 월은 기존 센터별 매출 전체를 분모에서 제외하고 ERP 매출만 사용합니다. 해당 월의 모든 매장 데이터를 올리는 것이 좋습니다. ERP가 없는 월은 과거 센터별 매출을 계속 사용할 수 있습니다. ERP 매출은 센터·국가·B2C/B2B별로 배분하지 않으므로 센터·국가·업무·비용 유형 필터를 좁히면 ERP 매출 기반 물류비율은 계산하지 않습니다. 매장·관리그룹·비용 항목 필터는 사용 가능하며 0 이하 매출은 물류비율을 표시하지 않습니다.

서버에서 앞서 메뉴 숨김을 위해 `index.html`을 직접 수정했다면 업데이트 전에 해당 파일의 변경만 `git stash push -- index.html`로 보관하세요. DB가 있는 data/나 백업 폴더는 건드리지 않습니다. 배포 브랜치의 실제 메뉴 제거가 적용되므로 옛 메뉴 숨김 변경을 다시 적용할 필요는 없습니다.

### 잘못 등록한 ERP 매출 삭제

매출 관리 표에서 행별 삭제 또는 체크박스 선택 삭제를 사용합니다. 헤더 체크박스는 현재 조회 월·관리그룹/매장에 보이는 집계 행만 선택합니다. 필터로 범위 밖이 된 선택은 해제되며, 삭제 미리보기 대상이 조회 범위를 벗어나면 확인 화면도 닫힙니다. 삭제 전 대상 월·매장코드·이름·그룹·금액 목록을 확인하고 동의 체크 후 최종 삭제합니다. 취소·선택만으로는 DB가 변경되지 않습니다.

삭제 대상은 `sales`의 월·매장별 ERP 집계 행입니다. 매장 마스터·비용·출고 건수·다른 매출 행·과거 activity/notes는 그대로 유지합니다. 확인 이후 대상 내용이 바뀌면 삭제를 차단하며 서버의 버전 충돌 검사도 적용합니다. 관리자와 입력 담당은 삭제할 수 있고 조회 담당은 삭제할 수 없습니다. 저장 전 자료는 기존 자동 스냅샷 보관 정책(최근 20개)에 따라 보관됩니다. ERP 매출을 해당 월에서 모두 삭제하면 보존된 과거 센터별 매출이 KPI 분모에 다시 사용될 수 있으며 삭제 확인 화면에 안내합니다.

ERP 매출 업로드에서는 앞자리 0을 보존한 매장코드를 연결 키로 사용합니다. 코드의 영문 대소문자는 정규화하며, ERP 매장명이 다르거나 비어 있어도 등록할 수 있습니다. 표시는 매장 마스터의 이름을 따르고 이름 차이는 코드별 경고로 모아 보여줍니다. 내부 ID와 과거 비용 연결은 변경하지 않습니다.

매출 표의 월·매장코드·매장명·관리그룹·매출 기준·ERP 원장 행 수·매출 금액 제목을 클릭하면 오름차순/내림차순 정렬을 전환합니다. 금액과 행 수는 숫자로, 코드는 문자열로 정렬하여 앞자리 0을 보존합니다. 방향 화살표와 접근성 정렬 상태를 표시하며 조회 계정도 사용 가능합니다. 정렬은 화면과 매출 CSV 순서에만 적용하고 저장 자료·선택된 삭제 대상 ID를 변경하지 않습니다.

### 비용 업무별 탭

비용 내역·업로드 화면에 전체 내역 / 물류센터 비용·건수 / 수출입 비용 / 공통 비용 탭을 제공합니다. 각 업무 탭은 해당 유형만 조회하고 필요한 열만 있는 전용 XLSX·CSV 양식을 제공합니다. 물류센터 양식은 센터·비용/건수·수량·단가, 수출입 양식은 선적 국가·수출입관리번호·인코텀즈·화물/컨테이너·문서번호·외화/환율, 공통 양식은 국가·매장/그룹·항목·금액 위주입니다. 비용유형은 선택한 전용 양식에 따라 자동 지정하고 수출입/공통은 비용으로 고정합니다.

업무가 다른 전용 양식을 올리거나 기존 통합 파일에 다른 유형이 섞여 있으면 전체 저장을 막습니다. 기존 양식도 해당 탭 유형만 포함하면 사용할 수 있으며 전체 내역 탭은 기존 혼합 업로드를 유지합니다. 빈 엑셀 행은 유형을 채워 새 기록으로 만들지 않습니다. 기존 금액 계산·외화 검증·중복 검사·실제 저장 시 재검증을 그대로 사용합니다. 탭을 바꾸면 저장하지 않은 검토를 닫을지 확인합니다. 탭별 직접 입력 버튼 및 상단 비용 등록은 해당 업무 화면으로 연결합니다. 조회 계정은 탭 이동과 양식 다운로드만 가능하고 업로드·직접 입력은 제한됩니다.

비용 화면에서는 유형 필터를 탭으로 대체하며, 수출입/공통 탭에서는 센터 필터를 숨기고 적용하지 않습니다. 월·국가·업무·비용 항목·매장/그룹 필터는 유지합니다. 탭 이동 자체는 저장된 비용을 변경하지 않습니다.

수출입 메뉴는 **수출입 비용 관리** 하나로 통합했습니다. 기본 건별 조회 탭에서 관리번호별 비용을 확인하고, 입력 권한이 있는 사용자는 비용 입력 탭 또는 상단 비용 등록 버튼으로 이동합니다. 작성 중 탭을 바꿔도 입력 내용은 유지되며, 저장하면 해당 월의 건별 조회 탭으로 돌아갑니다. 조회 전용 계정에는 입력 탭을 표시하지 않습니다.

디자인은 참조 ERP의 노란색을 포인트로 적용하고 차콜 사이드바·따뜻한 회백색 배경·흰 카드로 정리했습니다. 메뉴 아이콘은 기능별 SVG(요약 패널/창고/수출입 화살표/공통 분기/업로드 문서/매출 그래프/항목 태그/매장/위치 핀/계정 설정)로 통일했습니다. 아이콘은 장식으로 처리하고 텍스트 메뉴명을 유지합니다. 선택 메뉴와 주요 버튼은 어두운 글자·노란 배경이며, 표·차트·입력·로그인·모바일 화면에도 동일한 팔레트를 적용합니다. 삭제와 오류는 빨간색으로 구분합니다.

색상 최종 조정: 첨부한 타겟 이미지에 맞춰 레몬 옐로(#f2df3a) 내비게이션, 브라운(#6b582e) 표 헤더·선택 탭, 짙은 브라운(#5f491e) 주요 버튼, 쿨 그레이(#f4f5f7) 배경으로 변경했습니다. 기존 사이드바 구조와 기능은 유지합니다.

화면 정렬 보정: 상단 헤더는 사이드바 경계부터 본문 끝까지 연결하고 계정 입력 필드·권한 선택·추가 버튼은 높이 40px와 하단 기준선을 통일했습니다. 비용 내역 표는 탭별 컬럼을 사용합니다. 물류센터는 센터·비용/건수, 수출입은 관리번호·경로·문서·인코텀즈·외화, 공통은 국가·매장·항목·금액 중심입니다. 전체 내역은 통합 컬럼을 유지합니다.
